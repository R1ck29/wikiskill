# WikiSkill を利用者の代わりに動かす

利用者はターミナルに不慣れな業務担当者です。コマンドはすべてあなたが実行し、利用者に頼むのは
**例のフォルダを教えてもらうこと（A）と、新しい業務を覚えてよいかの確認（B）だけ**です（採点・書き出し先の選択・OK/NG 判定は頼まない）。
説明は専門用語を避けた短い日本語で行います。

## 実行方法とトークン節約（必ず守る）

`WS` は `python3 "${CLAUDE_SKILL_DIR}/scripts/run_wikiskill.py"` を表します（パスは必ずこの形でダブルクォート。
Windows は `python3` を `py`、無ければ `python` に）。
`WS` は単独で実行し、`;` `&&` `echo` などを付け足さない（終了コードは結果に表示される。付け足すと許可の確認が出る）。

- 最初に `WS check --no-call`。`claude`（または `codex`）が `NOT FOUND` なら、社内の手順で CLI を入れるよう伝えて止まる。
- 処理はコマンドに任せる。`raw/` `runs/` `wiki/` や実行記録は読まない。エラー時だけ `run.log` の末尾 30 行を読む。
- `improve` は Bash の `run_in_background` で実行し、完了通知を待つ（sleep・ポーリングしない）。
- 利用者の例ファイルは件数と形式がわかる分だけ見る。

終了コード: 0 成功 / 1 実行エラー（原因を直して同じコマンドを再実行すると続きから再開）/
2 入力の誤り（メッセージに従って直す）/ 3 人の判定待ち（利用者が人の判定を望んだときだけ。下の「人の判定」へ）。

## 置き場所（固定）

業務ごとに `~/wikiskill-work/<業務名>/suite`（スイート）と `~/wikiskill-work/<業務名>/workspace`（育成記録）。
業務名は英小文字とハイフン。育ったスキルは常に `~/.claude/skills` に自動で書き出す（利用者に聞かない）。
以下 `S`・`W` はそのスイートとワークスペースのパス。
コマンドが `cannot lock ... local drive` で止まったら、ホームがネットワークドライブなので、置き場所をローカルのフォルダ
（Windows は `%LOCALAPPDATA%\wikiskill-work`、それ以外は `/tmp` 以外のローカルディスク上のフォルダ）に変えて作り直し、利用者に一言伝える。
以後 `WS list` には `--root <その場所>` を付ける。

## A. 新しい業務を覚えさせる

1. 利用者に「例が入ったフォルダ」を 1 つ聞く（入力ファイルと、あれば正解）。
2. `WS init S --like sales-analysis --inputs <例のフォルダ>`（数値の答え。文章の業務は `--like translation-ja-en`）で
   `S` を作る（入力ファイルは `S/files/` にコピーされ、一覧が表示される）。`S/suite.json` を業務に合わせて直し、
   `S/tasks.jsonl` を 1 行 1 件で書く（書式は表示された完成例の tasks.jsonl と同じ。分割の目安: train 半分、
   val 4 分の 1、test 4 分の 1。各 1 件以上。少なければ test を減らす）。
   - `system_prompt` には `{skill_section}` と「最終回答を `<answer>...</answer>` で囲む」指示を残す。
   - 採点: 正解があり数値→`number`、決まった文言→`exact`/`contains`、出力ファイルの検査→`script`。
     **正解が無い・文章の業務は `llm_judge`** にし、例と利用者の説明から「良い結果の条件」を具体的に `rubric` に書く
     （用語・形式・必須項目など。利用者には確認しない）。
   - `WS check --suite S --no-call` が通るまで直す。
3. この環境で初めての育成なら、先に `WS check` を 1 回実行する（モデルを 2 回だけ呼び、認証とツールの許可を確かめる）。
   失敗したら表示された理由を伝えて止まる（対処は `docs/CONFIGURATION.md` の 1 章）。
4. `WS improve S --workspace W --export ~/.claude/skills` をバックグラウンドで実行
   （1 反復で train＋val 件数分のエージェント実行がかかり、API キーでは付属例の規模で 1 回数ドルの料金になることを一言伝える）。
5. 終わったら「最初の点数 → 最後の点数」「使えるようになったスキル名」を 2〜3 行で伝え、
   「結果が良い・違うと言ってもらえれば、それを覚えて自動で改善します」と添える。

## B. 利用者の評価を記録する（例がなくても育つ）

利用者が作業の結果を「良い」「違う（正しくは…）」と評価したら、その会話の中で次の順に進める。

1. **対象か判断する**: 依頼文と添付ファイルだけから同じ結果を作れる、繰り返しの業務（集計・翻訳・文書作成・定型の回答など）だけが対象。
   リポジトリのコードの変更、Web・社内システム・MCP に頼った作業、一度きりの質問は対象外で、何もせず何も言わない
   （育成では依頼文と添付ファイルだけを空のフォルダに置いて解き直すため、それ以外に頼る作業は学べない）。
2. **業務を選ぶ**: 育ったスキル（末尾に「Feedback for automatic improvement」がある）を使った結果なら、そこに書かれたスイートが `S`。
   それ以外は `WS list` で一覧を見て、入力の種類・出力の形・良し悪しの基準が同じ業務があればその `S` を使う。違う種類を混ぜない。
3. **無ければ一度だけ聞く**: 「この種類の作業（<業務の短い説明>）を覚えて、今後の評価から自動で改善しますか？
   依頼文・結果・添付ファイルが `~/wikiskill-work` に保存され、API キーでは改善のたびに料金がかかります」。
   断られたら記録せず、この会話では同じ業務について聞き直さない。了承されたら
   `WS init S --like translation-ja-en --workspace W --export ~/.claude/skills`（答えが数値の業務は `--like sales-analysis`）で作り、
   `S/suite.json` を A-2 の規則で直す（`name` は業務名、`task_description` は業務の説明、`llm_judge` の `rubric` は
   この会話の評価と利用者の言葉から書く）。タスクは書かない（評価から自動でたまり、6 件で最初の育成が自動で始まる）。
4. **記録する**: `WS feedback S --verdict good|bad --prompt '<利用者の依頼>' --output '<出した結果>'`
   （違うと言われ正しい内容がわかれば `--correct '<正しい結果>'`、理由は `--note '<理由>'`、入力ファイルは `--file <パス>` を足す）。
   `--prompt` には、依頼が前の会話に頼っていればその内容も含め、それだけで同じ作業ができる文にする。

記録の後:

- 終了コード 2 で `--correct` が必要と出たら、正しい答えを一言だけ聞く（答えがなければ記録しない）。
- 出力に `started` と出たら改善は自動で始まっている（何もしない）。`paused` と出たら今日の自動改善の上限に達しているので
  何もしない（翌日以降の記録で自動で再開する）。`ready` と出たときだけ、利用者に断らずに
  A-4 と同じ `improve` をバックグラウンドで実行し、終わったら 1 行で伝える。
- 出力に `warning: the last improve failed` または `warning: the last background start` があれば、前回の自動改善が失敗した原因を 1 行で伝える（記録は済んでおり、次の改善はいつもどおり自動で始まる）。
- 理由などを追加で聞かない。記録したことは「覚えました」と一言だけ伝える。`(a round starts at N)` の N に件数が届いていなければ
  「あと k 件の評価で改善を始めます」と添える。
- 文中に `'` を含むときは、その引数をダブルクォートで囲む（`"` `$` `` ` `` は `\` を前に付ける）。

## C. 続き・進み具合

`WS improve S --workspace W --export ~/.claude/skills` を再実行すれば途中から再開し、何もなければ「nothing to do」と出てスキルの書き出しだけ行う。
終了コード 1 で `another evolve or improve is running` と出たら自動の改善が実行中なので、そう伝えて終わる（`W/background.log` の末尾で様子がわかる）。
進み具合だけなら `WS status W`。スキルあり／なしの厳密な比較（`evaluate`・`compare`）は利用者が求めたときだけ。

## 人の判定（利用者が望んだときだけ）

`improve` に `--human-review on` を付ける。終了コード 3 で止まったら、表示された CSV のパスを伝え、
「Excel で開き、`verdict` 列に OK か NG（または 0〜1 の点数）を入れて保存し、終わったら『できた』と送ってください。
NG の行は `corrected_answer` に正しい答えを、`answer_key` 列は触らないでください」と頼み、返事が来たら同じコマンドを再実行する。
